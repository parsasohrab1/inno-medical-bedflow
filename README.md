# inno-medical-bedflow

**پیش‌بینی ظرفیت تخت و جریان بیماران**

> وضعیت: **TRL 4** — نمونه‌ی آزمایشگاهی با اعتبارسنجی اجزا روی **داده‌ی مصنوعی** (بدون داده‌ی بیمار). برای ارزیابی بالینی یا میدانی آماده نیست. ← [مستندات TRL](docs/TRL.md)

## نیاز شناسایی‌شده
کمبود تخت عمومی و ICU، تأخیر در ترخیص و پذیرش برنامه‌ریزی‌نشده.

## محصول
پیش‌بینی اشغال تخت بخش‌ها و پیشنهاد زمان‌بندی پذیرش و ترخیص.

## کاربران و ذی‌نفعان
مدیر پرستاری، مدیر بیمارستان، دانشگاه علوم پزشکی

## قابلیت‌های هدف
- پیش‌بینی اشغال هر بخش برای ۷ روز آینده
- پیشنهاد ترخیص‌های قابل‌تسریع
- داشبورد ظرفیت در سطح دانشگاه

## داده
سوابق پذیرش و ترخیص، نوع بخش، طول اقامت. در مراحل اولیه فقط داده‌ی مصنوعی یا بی‌نام‌شده استفاده می‌شود.

## ریسک‌ها و محدودیت‌ها
کیفیت ثبت داده‌ی HIS؛ تفاوت الگوها بین بیمارستان‌ها.

## مسیر پیشنهادی
1. ✅ TRL 1 → 2: تعریف نیاز و معیار موفقیت (جدول معیارها در [docs/TRL.md](docs/TRL.md)).
2. ✅ TRL 3: نمونه‌ی آزمایشگاهی روی داده‌ی مصنوعی همراه با تست.
3. ✅ TRL 4: اعتبارسنجی اجزا در آزمایشگاه با تست‌های خودکار (CI روی هر push).
4. ⬜ TRL 5: اعتبارسنجی در محیط مرتبط با داده‌ی واقعی بی‌نام‌شده — نیازمندی‌ها در [docs/TRL.md](docs/TRL.md).

## یادداشت
این ریپو بخشی از مجموعه‌ی `inno-medical-*` برای دانشگاه‌های علوم پزشکی و وزارت بهداشت است. هیچ‌یک از خروجی‌ها جایگزین قضاوت بالینی نیست.

## راه‌اندازی سریع
```bash
pip install -r requirements.txt           # فقط numpy
export PYTHONPATH=src
python -m inno_medical_bedflow generate --out data/sample # تولید داده‌ی مصنوعی (قطعی با seed)
python -m inno_medical_bedflow validate                   # اجرای معیارهای TRL 4 روی ۳ seed
python -m inno_medical_bedflow demo
python -m unittest discover -s tests -v
```

## آنچه پیاده‌سازی شده
پیش‌بینی سرشماری ۷ روزه با بقای تجربی مدت اقامت و نرخ پذیرش روز هفته، هشدار اشغال بالا، فهرست کاندیدای ترخیص (بر پایه‌ی پرچم آمادگی بالینی).
